# 12.2.8 — CRR Team Review Capability

**Parent:** 12.2 CRR Change Request
**Status:** Not Started

## Requirement
The CRR team must be able to review the request and either:
- Send it back to the submitter for clarifications, OR
- Update the status of the request as appropriate

Note: CRR team will track prioritization, tech reach out for build/effort assessments, approvals and moving change into production offline.

## Current Process (SharePoint Baseline)
- **Today:** GFCC-RMO team reviews requests by reading SharePoint list entries
- **Review actions:** Update "Status" column, add "GFCC-RMO Notes", update "Sign-off Status"
- **Clarification:** Done via email/Teams — no formal "send back" mechanism in SharePoint
- **Post-approval fields:** "Risk Data Element(s) Details", "Implementation scope (Enterprise/Market)", "Implementation Date"
- **Tracking columns:** "Required Approver(s)", "Approval Status", "PIV Created"
- **Offline activities:** Prioritization, tech effort estimation, and production deployment tracked outside SharePoint

## What 12.2.8 Aims to Digitize
- Dedicated review dashboard for CRR team
- Structured "Return for Clarification" action with comments (notification sent to submitter)
- Status update capability with audit trail
- Important scoping note: Prioritization, tech reach-out, effort assessment, and production deployment remain **offline** — platform handles governance workflow only, not implementation workflow

## Interview Notes
- Capability NOT yet built — part of future roadmap (Target PI 26.4)
- Intentionally limited scope: platform manages request lifecycle, NOT the implementation/build process
