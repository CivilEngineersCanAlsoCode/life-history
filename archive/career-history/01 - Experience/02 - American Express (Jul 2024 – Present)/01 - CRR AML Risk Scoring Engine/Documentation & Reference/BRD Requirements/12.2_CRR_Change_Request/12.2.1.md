# 12.2.1 — Change Request Submission Capability

**Parent:** 12.2 CRR Change Request
**Status:** Not Started (Target PI 26.4)

## Requirement
System should have capability to facilitate requests for CRR updates.

## Current Process (SharePoint Baseline)
- **Today:** Market MCO/MLRO teams submit a "CRR Customization Form" via SharePoint list at `teams/GFCC-RMO/Lists/CRR Customization Form`
- **Volume:** ~10 requests/month, 49 completed requests tracked historically
- **Form fields filled by requestor:** Requestor's Name, Request Date, Modification Reason, Modification Type (Add/Change/Remove), Modification Category (HRO/Data Element Weighting/Country Risk Rating Thresholds), Applicable Product Types, Applicable Location(s), Business Description, Supporting Documents
- **Post-submission:** AML Bank Approval (Approved by + Date), then GFCC-RMO implementation details

## What 12.2.1 Aims to Digitize
Replace the SharePoint form submission with an in-platform structured workflow:
- Form accessible directly within the CRR UI
- Structured field validation (vs. free-text SharePoint columns)
- Auto-capture of requestor identity from authenticated session
- Request ID generation for tracking
- Draft/submit lifecycle (save draft before final submission)

## Real Request Examples (from Production SharePoint Data)
| Request Type | Example |
|-------------|---------|
| HRO Override | Change PEP Present weighting from 4000 to 100 points (DE/AT) |
| FATF Approach | Remove HRO, apply multiplier of 9 instead (IT) |
| New Scoring Rule | Add geography corruption risk element at 4000 points (GNS Partner) |
| Bulk Regulatory | Certification changes — bulk rule updates for regulatory alignment |

## Interview Notes

- Separate from Sandbox: Sandbox = direct configuration changes by CRR business users; 12.2 = request workflow where market MCO/MLRO requests a change, CRR team reviews and implements
- May be updated/de-scoped based on TMRPO process review
