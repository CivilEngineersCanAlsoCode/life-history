# 12.2.2 — Permission-Based Access Control

**Parent:** 12.2 CRR Change Request
**Status:** Not Started (IAM blocking)

## Requirement
The access to the Change Request UI and the capabilities within (submit/review/disposition) should be based on permissions.

## Current Process (SharePoint Baseline)
- **Today:** Access controlled by SharePoint site permissions — anyone with access to the GFCC-RMO SharePoint site can view/submit
- **No granular capability-level control:** Submit, review, and disposition are not separately permissioned
- **SharePoint tracking columns:** "Assigned To", "Required Approver(s)", "Approval Status" — but these are manual column entries, not system-enforced RBAC

## What 12.2.2 Aims to Digitize
- Permission-based access to the Change Request UI (separate from Sandbox/Production view permissions)
- Capability-level entitlements: submit vs. review vs. disposition as distinct permissions
- Integration with enterprise IAM/IDP (currently blocking — IAM infrastructure not ready for this feature)
- Align with existing CRR user model: MCO (view-only in production) vs. CRR Business User (edit in sandbox)

## Dependencies
- IAM/IDP integration is a pre-requisite — currently the blocking factor
- Must align with broader CRR permission model being built for sandbox/production access

## Interview Notes
- Capability NOT yet built — blocked by IAM infrastructure readiness
- Part of future roadmap (Target PI 26.4)
