# 12.6 Centralized Lists / Fundamental Assessments / Notable Lists

**BRD Ref:** 12.6
**Status:** In Development (Target 26.3)
**Beads Task:** career-context-4y9

## Business Requirement
System should have the capability to setup and maintain all reference lists.

## Purpose
Capability to setup reference lists at multiple levels and have the ability to override locally.

## Outcome
Efficient and flexible system allowing for simpler implementation of reference lists.

## Major POD → POA Improvements (from Coaching)

### 1. Sandbox for Asset Manager & FA — NEW in POA
- **POD (Cadence):** No sandbox concept for assets or FA — changes went directly to production
- **POA (CRR 2.0):** Asset Manager and FA are now part of the unified sandbox workflow
- Edits to assets and FA are treated as sandbox changes, properly simulated, and impact shown before production push
- Atomic promotion: Rules + Assets + FA all push together in single transaction

### 2. FA Expansion — All 6 Gates
- **POD:** FA only partially worked for the **Geography gate**
- **POA:** FA enabled for **all 6 gates** (GR, IR, PRR, OCCP, ACR, SR)

### 3. Asset Manager Expansion — All Data Points
- **POD:** Asset Manager only worked for **5 data points**
- **POA:** Expanded to **ALL data points**, thoroughly used across all rule configurations

### 4. Asset Versioning — NEW
- Assets are now properly versioned (one new version on first change, inline updates until submit freezes)
- Enables easy editing and rollback within sandbox lifecycle

### 5. Versioning Architecture Gap
- **Versioned properly:** Assets, FA, Sandbox states
- **NOT versioned:** Rules/Risk Framework (categories, elements, rulesets) — uses static copy approach
- If rules used pointer-based versioning like Asset Manager, it would solve the sandbox refresh/staleness problem
- **Git analogy:** Static copy = being behind main after someone else merged; need a "git pull" equivalent for stale sandboxes
