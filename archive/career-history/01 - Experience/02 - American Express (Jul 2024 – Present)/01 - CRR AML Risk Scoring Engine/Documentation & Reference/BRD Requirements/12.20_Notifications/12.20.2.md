# 12.20.2 — Notification Content Details

**Parent:** 12.20 Notifications
**Status:** Not Started

## Requirement
The notification must include:
- Level at which change was detected
- % breach with before and after values
- Underlying reason for the breach (e.g., if a certain attribute was not populated at all or was at a different fill rate than usual)

## Coaching Notes
- Notification content must enable immediate triage without opening the dashboard
- "Underlying reason" detection = root cause analysis capability — distinguishing between:
  - Data quality issue (attribute not populated / fill rate change)
  - Framework change impact (rule update caused distribution shift)
  - Genuine population change (new customers, account closures)
- Before/after values provide the quantitative context for decision-making

## Interview Notes
- Not Started — Target 2027
- Root cause attribution is the most complex aspect — requires correlation between data pipeline health and scoring results
