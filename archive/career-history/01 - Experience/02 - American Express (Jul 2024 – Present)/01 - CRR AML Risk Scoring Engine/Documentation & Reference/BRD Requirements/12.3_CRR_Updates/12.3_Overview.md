## Sandbox Architecture — Critical Design Decisions

### Static Copy vs Pointer-Based Architecture
- **Current:** Static copy approach — sandbox creation takes a snapshot of CRR config at that instant
- **Implication:** If market sandbox is pushed to production (CRR version uplifts), any coexisting enterprise sandbox is still on old version
- **Trade-off:** No simultaneous enterprise + market sandboxes allowed (prevents version conflicts)
- **Acknowledged technical debt:** If rebuilding, would use pointer-based approach instead (confirmed by PM)

### Sandbox Scope
- **First sandbox = Enterprise** (blueprint for all markets)
- **Subsequent sandboxes = Market-level** or further enterprise edits
- Enterprise sandbox configures the global baseline; market sandboxes customize for local needs

### Sandbox Configuration Hierarchy
```
Sandbox (name, description, scope: Enterprise/Market)
  └── Risk Category (name, description)
       └── Risk Element (name, description, min, max, prohibited, time-based)
            └── Ruleset (description, logical conditions)
                 └── Rules (conditions with AND/OR operators)
                      └── Market Settings (default multiplier, applicability, weighting)
```

### Configuration Switcher
Dropdown inside sandbox to switch between:
- **Rules** editing screen
- **Asset** editing screen (create/edit assets, then link back to rules)
- **Fundamental Assessment** editing screen (edit FA, then link to rule multiplier)

### Rule Logic — Two Modes
- **Basic Mode:** AND operator only (simple conjunctive logic)
- **Advanced Mode:** AND + OR operators with parentheses for complex logic

## Sandbox Lifecycle (End-to-End)

### 1. Creation → Configuration → Simulation → Approval → Production

| Stage | Description |
|-------|-------------|
| Draft | User configures risk categories, elements, rulesets, rules, market settings, assets, FA |
| Simulation (click) | Shows all changes made to sandbox |
| Submit | PubSub/RTF event sent to Rule Execution Team |
| Submission In Progress | 2-3 min wait for Rule Execution Team acknowledgement (sim button disabled) |
| In Progress | Scoring calculation happening (target SLA: 10M accounts in ~2 hours; 85% improvement over Cadence) |
| Completed | Results available — Production vs Sandbox comparison dashboard |
| Cancelled | User cancelled simulation mid-run |
| Skipped | User skipped simulation entirely (no results, view results disabled) |
| Implement | User clicks Implement → 2-step approval flow |
| Approval Stage 1 | Same user can approve (mandatory comment) |
| Approval Stage 2 | DIFFERENT user must approve (mandatory comment) |
| Production | Atomic merge — rules + assets + FA in single transaction, no partial edits |
| Rejected | Any approval step rejected → can create new version or rollback |

### 2. Simulation Details
- **Modification screen:** Shows WHERE changes hit (risk elements, rulesets) — NOT exact values
- **Export button:** For exact change details
- **3-way impact switcher:** Rules / Assets / FA changes
- **Results dashboard:** Production vs Sandbox risk distribution
  - Grouped by: Center × Product × Legal Entity × Risk Score
  - Metrics: # accounts, # independent hierarchies, # hierarchical accounts, # customers, # obligor IDs
  - Risk bands: Low (1-3), Medium (4-6), High (7-9), Prohibited (10)

### 3. Version Management
- Max **10 versions** per sandbox
- **Create New Version:** From current state (new version, editable)
- **Rollback:** Dropdown to select previous version
  - No active draft → creates new version with previous config
  - Active draft exists → replaces current draft (no new version created)
- Config **frozen** once submitted (edits disabled)
- **History tab:** Version history, status changes, who/when/comments
- After 10 versions → must create new sandbox

### 4. Production Merge
- All components (rules, assets, FA) pushed in one go — single atomic transaction
- Sandbox becomes inactive (active flag = false), vanishes from sandbox list
- CRR version number uplifts
- MCO sees only their market's effective config (localized element takes priority over enterprise element)

## Interview Notes
- Complete end-to-end sandbox workflow confirmed during coaching
- Static copy architecture is known technical debt — pointer-based would be ideal but requires significant refactoring
- No simultaneous enterprise + market sandboxes = deliberate statistical trade-off
- Data points are pre-defined (user cannot create new data points)
- 3 ratio rule types (Income Type Ratio, Income Count Ratio, Transaction Ratio) restricted by UI — cannot have 2 aggregation-type data points together
- POA uses "Market" (standardized geographic) instead of POD's "Center" (customizable business-defined)
- Time-based flag = performance optimization: skip re-running rules when underlying data only changes monthly
- Market-level weighting override exists; Product/Legal Entity overrides are post-Phase 2 enhancement
