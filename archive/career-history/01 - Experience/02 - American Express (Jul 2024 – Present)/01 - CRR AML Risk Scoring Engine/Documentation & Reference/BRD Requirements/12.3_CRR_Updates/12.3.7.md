# 12.3.7 — Local Risk Elements Creation

**Parent:** 12.3 CRR Updates
**Status:** Partially built (missing Center/Legal Entity specific)

## Requirement
System should have the capability to create and identify a Risk Element as limited to certain centers/legal entities. Local Risk Elements will only apply to the markets that it has been tagged to.

## Confirmed Details (from Coaching)

### How Local Elements Work:
- Created inside a **market-level sandbox** (not enterprise sandbox)
- Tagged to specific markets/centers/legal entities
- Only apply to tagged markets — invisible to other markets
- **Priority over enterprise elements** when both exist for the same purpose

### Two Ways Local Elements Are Created:
1. **New local element:** Created from scratch in market sandbox (net-new, doesn't exist at enterprise level)
2. **Localized enterprise element:** Copy-on-write — enterprise element copied and customized for a market (diverges from enterprise, no future cascade)

### MCO Perspective:
- MCOs never see the "enterprise" vs "local" distinction
- They see the **effective configuration** for their market
- If an element has been localized → they see the local version
- If an element is enterprise-only → they see the enterprise version

### Current Status:
- **Built:** Market-level local elements (basic scope)
- **Missing:** Center-specific and Legal Entity-specific element scoping
- Need: ability to tag elements to specific centers (e.g., "International Products - D2") or specific legal entities within a market

## Interview Notes
- Local elements are key to regulatory compliance — different markets have different AML requirements
- Center/Legal Entity scoping is needed for markets with multiple products under different regulatory regimes
- Aligns with 12.3.4 (Enterprise vs Local tagging) and 12.3.6 (Weighting overrides)
