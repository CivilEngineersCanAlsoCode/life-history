# 12.3.4 — Enterprise vs Local Element Tagging

**Parent:** 12.3 CRR Updates
**Status:** In Development

## Requirement
System should have the capability of tagging an element as being at Enterprise level or Local level.

## Key Concept
Enterprise elements apply globally; Local elements apply only to tagged markets. This is the foundation for market customization with central governance.

## Confirmed Details (from Coaching)

### Enterprise vs Market Sandbox:
- **Enterprise sandbox** = first sandbox created = blueprint for all markets
- **Market sandbox** = subsequent sandboxes for market-specific customization
- Sandbox scope (Enterprise/Market) is specified at creation time

### How Enterprise/Local Tagging Works:
- **Enterprise Risk Element:** Created in enterprise sandbox, applies to ALL markets globally
- **Local Risk Element:** Created in market sandbox (or localized from enterprise), applies only to tagged markets
- When both enterprise and local versions exist for the same element: **local takes priority** in calculation
- **MCO view:** Never sees "enterprise" label — only sees effective config for their market
  - Enterprise concept is internal governance only, transparent to market users

### Copy-on-Write (Localization):
- When a market needs to customize an enterprise element → element is localized (copied) for that market
- Local copy diverges from enterprise — future enterprise changes don't cascade to localized elements
- This is the "copy-on-write at element level" pattern (confirmed in 12.1.5)

### Design Rationale:
- Central governance: Enterprise team sets global baseline
- Local autonomy: Markets customize for regulatory/business needs
- Transparency: MCOs see "what applies to me" without worrying about enterprise vs local origin

## Interview Notes
- Enterprise/Local tagging is foundational for 12.3.5 (global cascade), 12.3.6 (weighting overrides), and 12.3.7 (local elements)
- Static copy architecture adds complexity — localization means divergence, not just override
