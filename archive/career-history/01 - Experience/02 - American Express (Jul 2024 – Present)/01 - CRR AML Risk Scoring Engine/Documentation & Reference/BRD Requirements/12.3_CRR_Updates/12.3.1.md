# 12.3.1 — Risk Elements & Data Points Configuration

**Parent:** 12.3 CRR Updates
**Status:** In Development

## Requirement
System should have capability of setting up new Risk Elements / Data Points and weighting to the CRR framework. Should be a configurable feature — users should be able to set this up without going through a tech development cycle.

## Key Concept
Self-serve empowerment — analysts can create new risk elements without engineering involvement. Critical for agility in responding to new regulatory requirements.

## Confirmed Configuration Flow (from Coaching)

### Step-by-Step Inside Sandbox:

**1. Create Risk Category**
- Fields: Name, Description
- Maps to 5 fixed categories: Products/Services, Customer, Geography, Transaction, ARFs/HROs

**2. Create Risk Element (inside category)**
- Fields:
  | Field | Description |
  |-------|-------------|
  | Name | Risk element name (e.g., "PEP Present", "Country of Residence") |
  | Description | What this element measures |
  | Min/Max | Whether element takes MIN or MAX multiplier when multiple rules trigger |
  | Prohibited | Whether element can trigger prohibited (score 10) status |
  | Time-based | **Performance optimization flag** — for elements where underlying data changes monthly (e.g., Length of Relationship measured in months, monthly transaction volume). When flagged, system skips re-running the rule when data hasn't changed, reducing processing time. |

**3. Create Ruleset (inside element)**
- Fields: Description, Logical conditions
- **Two rule-building modes:**
  - **Basic Mode:** AND operator only — simple conjunctive conditions
  - **Advanced Mode:** AND + OR operators with parentheses — complex nested logic
- Rule = Datapoint + Operator + Value (confirmed from CRR-Context.docx)
- Multiple conditions combined into a ruleset

**4. Configure Market Settings**
- Default multiplier, Applicability, Weighting
- Applied per market (POA uses "Market" instead of "Center" from POD/Cadence)
- Market-level override exists; Product/Legal Entity override missing (future enhancement)

**5. Link Assets and FA**
- **Configuration Switcher:** Dropdown to jump between Rules ↔ Assets ↔ FA editing
- User creates/edits asset in Asset Manager → links back to rule
- User edits FA → links FA to rule multiplier for dynamic scoring

## Data Points
- **Pre-defined** — user cannot create new data points
- Data points come from customer data, transaction data, external reference data
- User selects from available data points when building rule conditions
- Certain data point combinations are restricted by UI (see 12.3.3)

## No-Code Configuration
- Everything above is done through the UI — no tech development cycle required
- CRR Business Users have full self-serve capability inside sandbox
- Guardrails enforced by UI (not backend validation) — restricted combinations, max versions, etc.

## Interview Notes
- Confirmed: complete configuration hierarchy (Category → Element → Ruleset → Rules → Market Settings)
- Basic vs Advanced mode for rule logic is a UX decision to reduce complexity for simple use cases
- Configuration Switcher is a key UX pattern — seamless context switching between Rules/Assets/FA
