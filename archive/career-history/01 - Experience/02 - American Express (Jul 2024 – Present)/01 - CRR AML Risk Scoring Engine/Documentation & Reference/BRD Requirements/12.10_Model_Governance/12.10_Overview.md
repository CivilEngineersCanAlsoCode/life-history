# 12.10 Model Governance

**BRD Ref:** 12.10
**Status:** Yes (Atomic Promotion supported)
**Beads Task:** career-context-4lh

## Business Requirement
System should be able to support a 2-step approval process for promoting an update into Production.

## Purpose
Maker-checker process for framework changes.

## Outcome
Control over any update made to the CRR framework.

## Sub-Requirements
| # | Description | Status |
|---|-------------|--------|
| 12.10.1 | Production Promotion Trigger | Yes |
| 12.10.2 | Two-Step Approval by Distinct Users | Yes |

## Confirmed Details (from 12.3 Coaching)

### How Approval Works in CRR 2.0:
- After simulation completes and results are reviewed, user triggers **production promotion**
- **2-step approval** by **distinct users** (maker-checker):
  - Approver 1 reviews and approves
  - Approver 2 (different person) reviews and approves
- Only after both approvals: **atomic promotion** to production
  - Rules + Assets + FA changes all merged in a **single transaction**
  - CRR version number incremented
  - All previous sandbox changes reflected in production

### Atomic Promotion Details:
- Production merge is **all-or-nothing** — no partial promotions
- Unified sandbox means rule changes, asset manager changes, and FA changes are promoted together
- Version history maintained for complete audit trail (see 12.7)

### Permission Dependency:
- Production promotion trigger is permission-based → depends on 12.21 (IAM)
- Currently functional for existing user roles, but fine-grained permissions pending IAM implementation
