# 12.10.2 — Two-Step Approval by Distinct Users

**Parent:** 12.10 Model Governance
**Status:** Yes

## Requirement
Request to move to production must require 2-step approval (must be distinct users).

## Confirmed Details (from Coaching)
- **Maker-checker pattern:** Two distinct users must approve
- Approver 1 ≠ Approver 2 ≠ Submitter (enforced by system)
- Both approvers review the full set of changes (rules + assets + FA)
- After both approvals: atomic merge to production, CRR version incremented
- If either approver rejects: sandbox returns to editable state, user can modify and re-submit

## Interview Notes
- Built and functional
- Critical for AML regulatory compliance — no single person can push changes to production
- Rejection flow allows iterative refinement without losing previous work
