# Capability: CRR Change Request

**BRD Ref:** 12.2

## Business Requirement
System should be capable of integrating the process of change request tracking and monitoring into the platform

## Purpose
Provide the ability to systemically request for market changes and manage it via the platform

## Outcome
Enhancing the process to improve efficiency in the way markets place ongoing customization requests and the way in which they are tracked and implemented (~10 / month)


## Discovery Questions
- [ ] Is 'Change Request' a metadata ticket or a distinct system entity?

## Development Status

**Status:** No
**Comments:** New Feature to be built for MCOs to submit/track changes. (Target PI 26.4)


## System Behavior & User Journey

**System Behavior:** A workflow engine (possibly integrated with an external ticketing system or custom-built) manages the lifecycle of configuration changes. While Atomic Promotion (12.10) handles the technical push, this feature manages the *governance*—tracking who requested the change, business justification, and multi-level approvals before the technical promotion is allowed.

**User Journey:** User identifies gap -> Opens Change Request Form -> Selects Affected Attributes -> Enters Justification -> Submits -> Approver receives notification -> Approver approves -> Change is queued for Sandbox/Production.
