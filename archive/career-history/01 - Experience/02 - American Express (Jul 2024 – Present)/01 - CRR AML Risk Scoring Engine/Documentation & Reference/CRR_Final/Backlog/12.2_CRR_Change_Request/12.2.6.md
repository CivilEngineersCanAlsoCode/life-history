# Sub-Requirement: 12.2.6

**Parent Capability:** [CRR Change Request](12.2_Capability.md)

## Description
They should have an option to set/select the following parameters:
> Applicable 'Market/Center', 'Legal Entity', 'Product' for the change (one or more)
> Type of change including rationale and driver (e.g., regulatory, others - comments being mandatory for others)


## Discovery Questions
- [ ] Is the 'Rationale' field mandatory for submission?
- [ ] Do we need a dropdown for 'Regulatory Driver' references (e.g. specific law ID)?

## Development Status

**Status:** No
**Comments:** New Feature to be built for MCOs to submit/track changes.


## System Behavior & User Journey

**System Behavior:** A workflow engine (possibly integrated with an external ticketing system or custom-built) manages the lifecycle of configuration changes. While Atomic Promotion (12.10) handles the technical push, this feature manages the *governance*—tracking who requested the change, business justification, and multi-level approvals before the technical promotion is allowed.

**User Journey:** User identifies gap -> Opens Change Request Form -> Selects Affected Attributes -> Enters Justification -> Submits -> Approver receives notification -> Approver approves -> Change is queued for Sandbox/Production.
