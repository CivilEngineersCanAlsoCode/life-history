## Q6. AI/ML Depth (When Relevant)

**Does this feature involve machine learning or AI, and if so, how?**

Sandbox Versioning itself is not an ML/AI feature. However, the Fundamental Assessment (FA) component that it orchestrates can incorporate ML models for risk scoring. CRR historically relied on rules-based risk assessment; FA modernizes this with ML-informed scoring. Sandbox Versioning provides the governance mechanism to test FA changes safely before production promotion.

**How does versioning interact with ML models?**

Fundamental Assessment changes can include: new feature engineering logic, retrained model weights, or updated calibration thresholds. When an analyst submits a sandbox with FA changes, the simulation environment must include the new ML model or scoring function. This requires: (a) model artifact versioning (tied to sandbox version), (b) reproducible inference (same input, same output across simulation runs and production), (c) model explainability for audit trails (why did risk score change?). Technical requirement: simulation must use the exact same model version and environment as production promotion.

**What are the ML-specific risks in the sandbox workflow?**

Risk 1: Model drift. If FA training data is stale, simulation results won't reflect production behavior. Mitigation: embed model retraining schedules into sandbox lifecycle (refresh models weekly/monthly). Risk 2: Inference reproducibility. If model inference is non-deterministic (e.g., floating-point precision, random seeds), simulation results are unreliable. Mitigation: enforce deterministic inference; version all model dependencies. Risk 3: Explainability gaps. MLRO teams approving sandboxes need to understand why FA changes shift risk scores. Mitigation: simulation results include feature attribution (e.g., SHAP values) or risk decomposition.

**How do you measure ML model quality in the sandbox context?**

Post-simulation, compare: (a) simulated risk scores vs. actual production scores (for past sandbox promotions), (b) model performance on holdout test set, (c) fairness metrics (are risk scores equitable across demographic groups?). These become continuous monitoring KPIs, not one-time validations. BRD 12.12 (real-time rescoring at onboarding) requires that models are validated continuously.

**What governance changes are needed for ML in sandboxes?**

Standard ML governance (model cards, bias audits, feature attribution) must be embedded into sandbox approval workflows. MLRO teams reviewing FA changes need model documentation. Audit trail must log not just "rule updated" but "model version X→Y, expected performance delta Z." This is higher-stakes governance than rule changes alone.

**Is there a phased approach to ML complexity?**

Phase 1 (current): Sandbox versioning for rules and assets (deterministic). Phase 2 (future): Fundamental Assessment with simple ML-informed features (supervised monitoring). Phase 3 (future): Complex ensemble models with continuous retraining (advanced monitoring required). Phase 1 does not depend on ML; it sets the governance foundation for Phase 2 and 3.
