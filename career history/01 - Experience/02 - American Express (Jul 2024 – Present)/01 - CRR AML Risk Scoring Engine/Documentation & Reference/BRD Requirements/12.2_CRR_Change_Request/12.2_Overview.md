# 12.2 CRR Change Request

**BRD Ref:** 12.2
**Status:** Not Started (Target PI 26.4)
**Beads Task:** career-context-89p
**Priority Note:** Medium priority — may be updated/de-scoped based on TMRPO process review

## Business Requirement
System should be capable of integrating the process of change request tracking and monitoring into the platform.

## Purpose
Provide the ability to systemically request for market changes and manage via the platform.

## Outcome
Enhancing the process to improve efficiency in the way markets place ongoing customization requests (~10/month) and the way in which they are tracked and implemented.

## Current Process (Confirmed from Coaching)

### SharePoint-Based "CRR Customization Form"
- **Managed by:** GFCC-RMO (Global Financial Crimes Compliance - Risk Management Office)
- **Location:** SharePoint list at `teams/GFCC-RMO/Lists/CRR Customization Form`
- **Volume:** ~49 completed requests tracked; ~10 requests/month

### Current Form Fields:
**User (MCO/MLRO) fills:**
| Field | Example Values |
|-------|---------------|
| Requestor's Name | Market compliance officer name |
| Request Date | Date of submission |
| Modification Reason | Best Practice / Regulatory Requirement / Examiner Expectation |
| Modification Type | Add / Change / Remove |
| Modification Category | High Risk Override / Data Element Weighting Value / Country Risk Rating Thresholds |
| Applicable Product Types | "All AENB Products", specific product codes |
| Applicable Location(s) | US, Germany and Austria, Italy, etc. |
| Business Description | Detailed free-text rationale |
| Supporting Documents | Regulatory translations, exam findings |

**Post-submission (AML Bank Approval):** Approved by + Date
**Post-submission (GFCC-RMO Team):** Risk Data Element(s) Details, Implementation scope (Enterprise/Market), Implementation Date

### SharePoint Tracking (Additional Columns):
- Assigned To, Status, Sign-off Status, GFCC-RMO Notes
- Required Approver(s), Approval Status
- PIV Created, Updated, Modified, Created By

### Real Request Examples (from Production Data):
- PEP HRO updates — change PEP Present weighting from 4000 to 100 points (DE/AT)
- FATF approach changes — remove HRO, apply multiplier of 9 instead (IT)
- GNS Partner scoring — add geography corruption risk elements at 4000 points
- Certification changes — bulk rule updates for regulatory alignment

### What 12.2 Aims to Achieve:
Digitize this SharePoint form into an in-platform change request workflow with:
- Structured submission through CRR UI
- Automated assignment and routing
- Real-time status tracking
- Notifications at each lifecycle step
- Complete audit trail (vs. manual SharePoint column updates)

## This Capability is NOT yet built — it is on the future roadmap (Target PI 26.4)
**Separate from Sandbox:** Sandbox = direct configuration changes by CRR business users. 12.2 = request workflow where market MCO/MLRO requests a change, CRR team reviews and implements.
