# 12.1.3 — Multiplier Configuration

**Parent:** 12.1 CRR Structure and Setup
**Status:** In Development

## Requirement
- The multiplier of a risk element is set based on rule criteria
- System should have ability to have multiple rulesets
- System should have ability to combine data points to establish criteria
- For each element, users should be able to identify minimum or maximum multiplier
  - Minimum for: Length of Relationship, Acquisition Channel
  - Maximum is set for all others (potentially default)
- System should have the ability to setup rule to trigger based on Fundamental Assessment risk score (1-10) / Centralized Lists
  - Example: In 7,8,9 for high risk geographies
- System should have the ability to setup a default multiplier (when data is unavailable)

## Key Concept
Multiplier can be either a static value OR derived from a Fundamental Assessment gate score. This is what makes the scoring dynamic — the same rule can produce different multipliers for different customers based on their FA scores.

## Two Multiplier Types (Confirmed from Coaching)

### 1. Value-Based Multiplier (Static)
- **Range:** 0 to 99 (decimal values allowed, e.g., 1.5, 3.7)
- **Limit:** Set via UI, no hard/fast criteria
- **Use:** Rule creator manually assigns a fixed multiplier value
- **Example:** IF country = "Iran" THEN multiplier = 5

### 2. FA-Based Multiplier (Dynamic)
- **Mechanism:** System pulls the **inherent risk score** from the Fundamental Assessment table for the customer's actual attribute
- **Range:** 1 to 10 (FA inherent risk scores)
- **6 FA Gates available:**
  | Code | Gate Name | What it scores |
  |------|-----------|---------------|
  | GR | Geography | Countries and regions |
  | IR | Industry | Industry classifications |
  | PRR | Product | Product types |
  | OCCP | Occupation | Customer occupations |
  | ACR | Acquisition Channel | How customer was acquired |
  | SR | Structure | Entity/legal structure |

- **Example flow:**
  1. Rule specifies FA gate = "Geography"
  2. System looks up Geography FA table
  3. All geographies listed with their inherent risk score (1-10)
  4. Customer's geography inherent risk score becomes the multiplier
  5. Risk Points = Weighting × FA-derived multiplier

### FA Inherent Risk Calculation
- Separate process inside Fundamental Assessment
- Each attribute assessed for fundamental/inherent risk
- 10 ranked questions per attribute
- Score = highest ranked question answered "YES"
- This score (1-10) feeds back into CRR as the dynamic multiplier

### Min/Max Multiplier Resolution (When Multiple Rules Trigger)
When multiple rules trigger under a single element, the element's min/max type determines resolution:

| Element Type | Resolution | Reason |
|-------------|-----------|--------|
| **Most elements** | Take **MAXIMUM** multiplier | Worst-case risk capture |
| **Length of Relationship** | Take **MINIMUM** multiplier | Inverse: longer relationship → more trust → less risk |
| **Acquisition Channel** | Take **MINIMUM** multiplier | Inverse: older channel → more data → less risk |

### Default Multiplier
- Applied when data is unavailable (fallback scoring)
- Ensures every element contributes a score even with incomplete data

## Why This Design Is Powerful
- **Value-based** = direct analyst control (simple, explicit)
- **FA-based** = automatic dynamic scoring — same rule produces different multipliers per customer based on their actual attributes
- Example: India (GR inherent risk = 3) vs. Iran (GR inherent risk = 9) → same weighting, but 3× higher risk points for Iran customer
- This combination enables both **precision** (FA-based) and **flexibility** (value-based override)

## Discovery Questions (Answered)
- **Version control for individual elements?** → Yes, handled through Sandbox versioning system (see 12.8)
- **Historical score impact if element renamed?** → Versioning preserves history; renames create new version
