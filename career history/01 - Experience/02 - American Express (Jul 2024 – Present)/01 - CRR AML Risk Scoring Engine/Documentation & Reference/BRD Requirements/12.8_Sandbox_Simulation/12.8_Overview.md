# 12.8 Sandbox - Simulation Functionality

**BRD Ref:** 12.8
**Status:** In Development (Simulation/Integration pending)
**Beads Task:** career-context-oci

## Business Requirement
System should support sandbox simulation functionality providing multiple instances and effective monitoring capabilities.

## Purpose
Ability to run simulations at enterprise and local level.

## Outcome
Comprehensive view of the impact of any change on the customer population.

## Confirmed Details (from 12.3 Coaching — Complete Simulation Flow)

### Simulation Lifecycle:
1. User clicks **Simulation button** → shows all changes made to sandbox
2. **Submit** → PubSub/RTF event sent to Rule Execution Team
3. **Submission In Progress** → 2-3 min wait for Rule Execution Team acknowledgement (sim button disabled)
4. **In Progress** → Scoring calculation running
5. **Completed** → Results available (Production vs Sandbox comparison)
6. **Cancelled** → User can cancel mid-run (cancel request → ack from Rule Execution Team)
7. **Skipped** → User can skip simulation entirely (no results, view results disabled)

### Key Simulation Features:
- **Modification screen:** Shows WHERE changes impacted (risk elements, rulesets) — NOT exact values
- **Export button:** Exact change details downloadable
- **3-way impact switcher:** Impact from Rules / Assets / FA changes
- **Results dashboard:** Production vs Sandbox risk distribution comparison
  - Grouped by: Center × Product × Legal Entity × Risk Score
  - Metrics: accounts, hierarchies, customers, obligor IDs
  - Risk bands: Low (1-3), Medium (4-6), High (7-9), Prohibited (10)
- **Version management:** Up to 10 versions, create new / rollback to previous

### Sandbox Constraint (Static Copy):
- No simultaneous enterprise + market sandboxes (version conflict)
- 12.8.13 (In-Flight Changes Merge) directly maps to this problem — "git pull" equivalent needed
- Static copy approach = known technical debt; pointer-based would solve refresh problem

### Performance Target:
- **SLA:** 10M accounts in ~2 hours (85% improvement over Cadence)
- BRD vendor POC benchmark: 10M accounts in 5 hours — CRR 2.0 targets better than this
