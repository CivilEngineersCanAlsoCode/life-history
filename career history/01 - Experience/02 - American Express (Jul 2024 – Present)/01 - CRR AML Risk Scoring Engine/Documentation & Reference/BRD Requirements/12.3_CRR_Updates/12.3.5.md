# 12.3.5 — Enterprise Element Global Applicability

**Parent:** 12.3 CRR Updates
**Status:** In Development

## Requirement
Enterprise Risk Elements should be applicable to ALL CRR assessments (across all markets). The update made once at the enterprise level should flow down to all markets assessments.

## Key Concept
Single change → global cascade. Eliminates the need to manually replicate changes across 40+ markets.

## Confirmed Details (from Coaching)

### How Global Cascade Works:
1. Enterprise sandbox created → changes made to enterprise risk elements
2. Enterprise sandbox pushed to production → atomic merge (rules + assets + FA)
3. CRR version uplifts → all markets inherit the enterprise-level changes
4. **Exception:** Markets that have localized (copy-on-write) versions of an element do NOT get the cascade — their local version takes priority

### Architecture Constraint:
- **Static copy approach** means enterprise sandbox is a snapshot at creation time
- No simultaneous enterprise + market sandboxes allowed
- If market sandbox pushed first → CRR version changes → enterprise sandbox still on old version (stale)
- This is a known limitation — pointer-based approach would solve this but requires significant refactoring

### Cascade Logic:
```
Enterprise element change pushed to production
  ├── Market A (no local override) → ✅ Gets cascade automatically
  ├── Market B (localized element) → ❌ Local version takes priority, no cascade
  └── Market C (no local override) → ✅ Gets cascade automatically
```

### What This Means for MCOs:
- MCOs in markets without local overrides automatically see enterprise changes after production push
- MCOs in markets with localized elements continue to see their local version
- No manual replication across 40+ markets needed (was the biggest pain point in Cadence)

## Interview Notes
- Global cascade only applies to non-localized enterprise elements
- Localized elements are intentionally excluded from cascade (by design — local autonomy)
- Static copy architecture is the biggest technical constraint on this feature
