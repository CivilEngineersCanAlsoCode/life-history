# BRD 12.12.2 — Override Feedback Loop

## Parent Requirement
12.12 — Integration with AML Ecosystem

## Status
Not Built

## Requirement
If interfacing systems override Risk Rating, the same must be consumed by CRR application with details (what/who/why/when).

## Key Details
- CRR application must consume overrides from interfacing systems
- Override details captured: what was changed
- Override details captured: who made the change
- Override details captured: why the change was made
- Override details captured: when the change occurred
- Bidirectional feedback loop between CRR and consuming applications

## Coaching Notes
- Connects to 12.4.3 (Manual Risk Rating Override): CRR already supports manual overrides from FIU/MCO
- This extends that capability to overrides originating from EXTERNAL systems (KYC, AML Investigations)
- Override is **permanent** (from 12.4.3 coaching) — if downstream system overrides, CRR must honor it permanently
- Audit trail (12.7) must capture external system overrides with same what/who/why/when detail
