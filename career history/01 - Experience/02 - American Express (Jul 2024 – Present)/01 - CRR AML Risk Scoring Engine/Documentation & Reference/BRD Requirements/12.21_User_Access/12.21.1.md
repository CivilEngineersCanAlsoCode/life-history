# 12.21.1 — Permission-Based Access Configuration

**Parent:** 12.21 User Access
**Status:** BLOCKING

## Requirement
User access to various functions will be permissions based. The specific groups/users that will have access will be finalized as part of the PRD.

## Key Concept
This is a foundational capability. Without it, the following features cannot be fully implemented:
- 12.2.2/12.2.3: Change Request access control
- 12.3.2: CRR Update permissions
- 12.6.4: List access control
- 12.8.3: Sandbox access control
- 12.9.4: Results view-only access

## Coaching Notes
- IAM = Identity and Access Management — foundational infrastructure dependency
- Permission model must support: view, edit, approve, download at Enterprise/Market/Product/LE scope
- Key principle: **least privilege** — users only see/do what their role requires
- FIU needs override capability (12.4.3) but not framework editing capability
- MCO/MLRO need results viewing (12.9.4) but potentially not simulation trigger (12.8.3)
- 2-step approval (12.10.2) enforces distinct users — IAM must validate user identity and role

## Interview Notes
- BLOCKING — the foundational capability that enables fine-grained access control across the entire CRR application
- Groups/users finalized in PRD, not BRD — BRD defines the capability, PRD defines the specific permissions
