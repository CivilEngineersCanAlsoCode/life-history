# Sub-Requirement: 12.2.3

**Parent Capability:** [CRR Change Request](12.2_Capability.md)

## Description
For the default setup, only MLRO teams should be able to submit a request. Only the core CRR team (Tommy's team) should be able to review and disposition the request.


## Discovery Questions
- [ ] If only MLRO teams can submit, what happens if a central policy team needs to initiate a change?
- [ ] Is the 'Core CRR Team' a fixed list of users or a role-based group?

## Development Status

**Status:** No
**Comments:** Features related to IAM/Permissions are not yet implemented.


## System Behavior & User Journey

**System Behavior:** Identity and Access Management (IAM) is handled via the enterprise Identity Provider (IDP). The application enforces Role-Based Access Control (RBAC). Roles (e.g., 'Analyst', 'Approver', 'Admin') are mapped to specific API endpoints and UI components. This ensures users only see/edit what they are entitled to.

**User Journey:** User logs in -> System validates Token -> Fetches Permissions -> UI renders enabled/disabled buttons based on permission set.
